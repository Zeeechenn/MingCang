## Allowed contribution boundary

| Role | May contribute | Must not control |
|---|---|---|
| Detect-like | confirmed-pivot causality, normalized zone geometry, touch/hold/trade separation, placebo and distance tests | official probability, production signal or stop |
| Alpha-like | restricted formula representation, causal rolling features, candidate de-correlation and explicit search budget | champion formula, adaptive validation result or production weight |
| TSP-like | matrix research, nested walk-forward, candidate artifact/signature, save/retest workflow | MingCang DB writes, arbitrary plugins, release/promotion or production PnL ledger |
| PA-like | frozen analysis frame, two-stage schema, semantic consistency and prompt/token audit | weights, execution or treating notification as a fill |
| MingCang | PIT data, executable replay, costs, benchmark, locked holdout, forward shadow, evidence ledger and owner decision | accepting external PnL as independent proof |

The only durable exchange object is a versioned Candidate Manifest containing
identity/signature, hypothesis and failure conditions, close-confirmed data
snapshot/hash, full search family and budget, random seeds, holdout-access
record, strategy and execution contract, inner/outer folds, purge/embargo,
costs/benchmark, failed/null results, data-quality checks, lifecycle, owner,
consumer, expiry and rollback. Any definition change creates a new candidate ID.

## Independent validation requirements

1. MingCang exports a read-only close-confirmed snapshot; external tools receive
   no production credentials or write path.
2. MingCang reconstructs signal time, fills, costs, benchmark and portfolio NAV
   with its own implementation. Shared data or implementation contamination is
   disclosed and cannot be called independent validation.
3. Historical testing uses PIT inputs, purged/nested walk-forward, one untouched
   locked holdout, block-aware uncertainty, capacity, turnover, drawdown and
   multiple-testing control.
4. Forward comparison freezes the current production control and changes one
   preregistered variable. The candidate writes only an isolated shadow/paper
   ledger until all gates and owner confirmation pass.
5. Support/resistance is only one possible P3 hypothesis. It is selected only if
   P0-R loss attribution identifies a matching loss mechanism.

## Security and licensing gates

- Do not run PA_Agent with real credentials until the upstream secret is revoked,
  history is cleaned, and secret scanning is enforced.
- Keep TSP isolated, loopback-only or offline until its raw SQL sink is removed;
  provide only a versioned read-only snapshot.
- Do not copy GPL/AGPL source expression into MingCang. If a Detect-like method is
  selected, the source reader writes only a public-method specification and
  adversarial tests; an implementer who has not read the upstream source writes
  the code, with both roles and references recorded.
- License notes are engineering risk controls, not legal advice.

## Evidence limitations

- Detect's reported 20/200-stock evaluations lacked public OHLCV and a complete
  public protocol. A 24-symbol random-walk negative control found no positive
  noise alpha, but it did not prove real-market alpha.
- AlphaMaster's roughly 1.728 million nominal candidate evaluations illustrate
  severe multiple-testing risk; a high validation winner is not final holdout.
- PA_Agent's first strict consistency test failed after dependencies were added;
  long GUI/network tests were not completed.
- TSP's engine was reproducible in the fixed snapshot, but its MingCang-price
  experiment used a price base later shown to contain mixed providers. Direction
  and magnitude must be rerun after price-basis cleanup.
- All claims are pinned to the commits above and may be stale after upstream
  changes. Re-audit before reuse.
